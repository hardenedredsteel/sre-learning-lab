# Процессы: базовая диагностика

## Цель

Быстро понять, какой процесс потребляет CPU/память и как его безопасно остановить.

## Симптомы

- Сервер «тормозит», SSH отвечает медленно.  
- Мониторинг показывает высокий CPU или память на хосте.

## Команды проверки

```bash
# Общая картина по CPU и памяти
top -bn1 | head -n 20

# Более удобный вывод (если установлен)
htop

# Процессы, отсортированные по CPU
ps aux --sort=-%cpu | head -n 10

# Процессы, отсортированные по памяти
ps aux --sort=-%mem | head -n 10
```

## Как читать вывод

- `top`:
  - строка `%Cpu(s)` показывает загрузку CPU;
  - в списке процессов важны столбцы `%CPU` и `%MEM`.
- `ps aux`:
  - ключевые столбцы: `%CPU`, `%MEM`, `COMMAND`.

## Безопасное исправление

```bash
# Уточнить владельца, состояние, команду запуска и родительский процесс
ps -p <PID> -o pid,ppid,user,stat,%cpu,%mem,etime,cmd

# Если это systemd-сервис, предпочтительнее остановить именно сервис
systemctl status <service-name>
sudo systemctl stop <service-name>

# SIGTERM: попросить процесс штатно завершиться
kill <PID>

# SIGKILL: крайняя мера после проверки причины и ожидания
kill -9 <PID>

# Посмотреть состояние процесса и точку ожидания в ядре
ps -p <PID> -o pid,stat,wchan,cmd

# Найти все процессы в состоянии D (непрерываемое ожидание, часто I/O)
ps -eo pid,stat,comm | awk '$2 ~ /^D/ {print}'
```

## Проверка результата

```bash
# Убедиться, что процесс исчез
ps -p <PID>

# Оценить общую нагрузку снова
top -bn1 | head -n 5
```

## Типичные ошибки

### 1. `kill -9` без попытки обычного `kill`

Для systemd-сервиса безопаснее начать с:

```bash
systemctl stop <service>
```

Почему:

- `systemctl stop` использует политику остановки unit’а:
  - приложение получает штатный сигнал завершения;
  - успевает закрыть соединения и файлы;
  - завершить дочерние процессы;
  - освободить ресурсы.
- `kill -9` (SIGKILL) нельзя обработать:
  - процесс убивается мгновенно;
  - может остаться «мусор» (залоченные файлы, зависшие соединения и т.п.).

**План действий:**

1. Сначала:  
   ```bash
   systemctl stop <service>
   ```
2. Если не помогает и процесс явно «завис»:
   - проверить, не в состоянии ли он `D` (I/O):
     ```bash
     ps -p <PID> -o pid,stat,wchan,cmd
     ps -eo pid,stat,comm | awk '$2 ~ /^D/ {print}'
     ```
   - если много процессов в `D` — диагностировать storage/ФС, а не просто убивать процессы.
3. Только если штатное завершение не сработало и причина понятна:
   ```bash
   kill <PID>      # SIGTERM
   # подождали несколько секунд
   kill -9 <PID>   # SIGKILL, крайняя мера
   ```

### 2. Остановка системных процессов без понимания их роли

- Не убивать наугад процессы с именами вроде `systemd`, `journald`, `sshd`, `NetworkManager` и т.п.
- Перед действием:
  - посмотреть, за что отвечает сервис:
    ```bash
    systemctl status <service>
    systemctl cat <service>
    ```
  - оценить влияние на другие сервисы и пользователей.
